# 2. Conceptos clave

## 2.1 Definición de Tokenización (reversible)

**Definición respaldada**
Según el PCI Security Standards Council, la **tokenización** es un proceso mediante el cual un valor sensible es sustituido por un **token no sensible**, manteniendo una **relación de mapeo segura y controlada** que permite **revertir** el token y recuperar el valor original cuando se cuente con los permisos y mecanismos adecuados. La seguridad del sistema depende del **Token Vault**, el cual debe estar aislado y gestionado con controles estrictos de acceso, auditoría y criptografía.
Fuente: PCI SSC, 2011 y 2015.

**Características técnicas clave según estándares PCI DSS**

* Reversible mediante mecanismos autorizados.
* No requiere cifrado dentro del token, pero puede coexistir con cifrado.
* El token no debe permitir deducir el valor original.
* El Token Vault suele operar en infraestructura protegida (HSM, enclave seguro o servicio KMS).
* El token puede preservar formato (FPE) o no, según requerimientos del sistema.

**Implicación regulatoria**
De acuerdo con GDPR y NIST, la tokenización se considera una **seudonimización**.
No se considera anonimización porque un tercero con acceso indebido al Token Vault o a las claves podría revertir el valor.

---

## 2.2 Definición de Anonimización (irreversible)

**Definición respaldada**
La **anonimización** es un proceso mediante el cual los datos personales se transforman de un modo **irreversible** para impedir que una persona pueda ser identificada **directa o indirectamente**, incluso mediante información adicional razonablemente disponible.
Fuentes: GDPR Recital 26; NIST IR 8053; ICO; PDPC (2024).

**Elementos técnicos clave**

* Debe eliminar o transformar atributos directos e indirectos que permitan inferir identidad.
* No existe un método universal; la eficacia depende del contexto del dataset y riesgo residual.
* Técnicas comunes (según NIST e ICO):

  * Generalización
  * Supresión
  * Agregación
  * Perturbación / noise
  * K-anonymity, l-diversity, t-closeness
  * Differential Privacy (según literatura académica; no siempre suficiente por sí sola)

**Implicación regulatoria**
Una vez los datos están **anonimizados correctamente**, **ya no se consideran datos personales** bajo GDPR y dejan de aplicar obligaciones de protección de datos personales.
Fuente: GDPR Recital 26 y guías del ICO.

---

## 2.3 Comparación conceptual

| Elemento            | Tokenización (seudonimización)                            | Anonimización                                          |
| ------------------- | --------------------------------------------------------- | ------------------------------------------------------ |
| Reversibilidad      | Sí, bajo control estricto                                 | No, debe ser irreversible                              |
| Base legal          | Sigue siendo dato personal bajo GDPR                      | Queda fuera de ámbito GDPR                             |
| Componentes típicos | Token Vault, HSM/KMS, control de acceso                   | Técnicas matemáticas y estadístico-contextuales        |
| Finalidad común     | Procesos operativos, flujos transaccionales, CRM, soporte | Analítica, IA, investigación, compartición segura      |
| Riesgo si se filtra | Alto si vault o llaves se comprometen                     | Depende de la calidad de anonimización y del contexto  |
| Complejidad         | Media-alta (infraestructura y custodia)                   | Alta (análisis de riesgo + métodos multidimensionales) |
| Ejemplo típico      | Reemplazar número de tarjeta o CURP                       | Dataset clínico anonimizado para investigación         |

**Síntesis operacional**

* **Tokenizar** = cambiar *identificadores* sin perder trazabilidad.
* **Anonimizar** = eliminar *posibilidad práctica de asociación con un individuo*.

---

## 2.4 Respuesta explícita a la diferencia operativa y técnica

* En tokenización, el dato original **continúa existiendo** y puede recuperarse mediante un proceso autorizado; la confidencialidad depende del **control de llaves o vault**.
* En anonimización, **no existe forma razonable de recuperar el dato original**, y su validez depende de pruebas de **no reidentificación**, contexto y controles auxiliares, no solo de transformaciones sintácticas.
