# 8. Referencias y herramientas

Esta sección reúne **normativas, guías, herramientas, librerías y plataformas** que pueden emplearse para implementar soluciones basadas en **tokenización** y **anonimización** dentro de entornos técnicos con IA y LLMs. Todas las referencias citadas son públicas, verificables y reconocidas.

## 8.5 Recomendación final de adopción empresarial escalable

Para un **entorno que use LLMs con datos reales**, la arquitectura mínima aconsejable es:

* LLM externo o interno **protegido por API Gateway con inspección DLP**
* Tokenización en backend con **HashiCorp Vault + KMS**
* Logs protegidos, anonimizados y con retención mínima
* Políticas internas **Privacy by Design + Zero-Trust**
* Validación trimestral de **riesgo de reidentificación**
* Auditorías basadas en **NIST + ISO + GDPR**

## **8.6 Glosario**

| Término                                       | Definición clara y técnica                                                                                                                                                                                                  |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Anonimización**                             | Proceso permanente e irreversible mediante el cual se transforma información personal para impedir la identificación directa o indirecta de una persona, incluso utilizando información adicional razonablemente accesible. |
| **API (Application Programming Interface)**   | Interfaz que permite a un software interactuar con otro sistema, servicio o plataforma, generalmente mediante intercambio estructurado de datos u órdenes.                                                                  |
| **Confidential Computing**                    | Enfoque de seguridad basado en hardware que protege datos en uso mediante entornos de ejecución confiables (TEE), evitando accesos no autorizados incluso desde el propio sistema operativo o hipervisor.                   |
| **Cifrado (Encryption)**                      | Técnica criptográfica reversible para proteger datos durante almacenamiento o transmisión, mediante llaves de cifrado/descifrado. No transforma el dato en anónimo, solo en inaccesible sin autorización.                   |
| **DLP (Data Loss Prevention)**                | Conjunto de herramientas y políticas diseñadas para detectar, bloquear o monitorizar transferencias no autorizadas de información confidencial a través de sistemas, redes y aplicaciones.                                  |
| **DP (Differential Privacy)**                 | Marco matemático que introduce ruido estadísticamente controlado a los datos o resultados agregados, manteniendo patrones estadísticos útiles mientras se oculta la contribución individual.                                |
| **HSM (Hardware Security Module)**            | Dispositivo físico de alta seguridad diseñado para almacenar, gestionar y operar criptografía con llaves sin que puedan ser extraídas.                                                                                      |
| **KMS (Key Management Service)**              | Servicio administrado para generación, almacenamiento, rotación y control de llaves criptográficas. Suele ser ofrecido por proveedores cloud (AWS, Google Cloud, Azure).                                                    |
| **LLM (Large Language Model)**                | Modelo de lenguaje basado en redes neuronales profundas entrenado con grandes volúmenes de texto, capaz de generar lenguaje natural, responder preguntas y procesar instrucciones.                                          |
| **PII (Personally Identifiable Information)** | Información que permite identificar directa o indirectamente a una persona, incluyendo identificadores explícitos (nombre, correo, CURP) y atributos combinables (edad, ubicación, ocupación).                              |
| **PHI (Protected Health Information)**        | Datos médicos vinculados a un individuo que están protegidos bajo regulaciones específicas (como HIPAA en Estados Unidos).                                                                                                  |
| **Pseudoanonimización / Seudonimización**     | Técnica que reemplaza identificadores reales por valores alternativos o tokens, preservando la posibilidad de revertir la relación bajo controles seguros. No constituye anonimización.                                     |
| **Token**                                     | Valor sustituto no sensible que reemplaza temporalmente datos reales manteniendo estructura o semántica operativa, sin permitir inferir el dato original.                                                                   |
| **Token Vault**                               | Componente seguro diseñado para almacenar y gestionar las relaciones entre tokens y datos originales, con controles estrictos de acceso y auditoría.                                                                        |
| **FPE (Format Preserving Encryption)**        | Forma de cifrado en la que el resultado mantiene el formato del dato original (longitud, tipo de caracteres, máscara), facilitando compatibilidad con sistemas existentes.                                                  |
| **Quasi-identificadores**                     | Atributos que individualmente no identifican a una persona, pero en combinación con otros factores contextuales podrían permitir reidentificación (ej.: código postal + edad + fecha de atención).                          |
| **RBAC (Role-Based Access Control)**          | Modelo de control de acceso basado en roles definidos, donde permisos están ligados a perfiles laborales y no a individuos.                                                                                                 |
| **ABAC (Attribute-Based Access Control)**     | Modelo de control de acceso basado en atributos (contexto, tiempo, ubicación, confidencialidad), permitiendo políticas más granulares que RBAC.                                                                             |
| **Trazabilidad**                              | Capacidad de seguir la secuencia de interacciones o transformaciones de un dato sin necesidad de exponer su contenido real.                                                                                                 |
| **Reidentificación**                          | Proceso mediante el cual un individuo supuestamente anónimo es identificado mediante correlación con información adicional interna o pública.                                                                               |
